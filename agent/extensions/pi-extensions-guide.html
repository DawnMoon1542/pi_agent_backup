扩展分类总览

整个扩展集合围绕 Pi coding agent 的 ExtensionAPI 构建，通过 pi.on() 监听生命周期事件、pi.registerTool() 注册自定义工具、pi.registerCommand() 注册命令、pi.registerProvider() 注册模型供应商，覆盖了 TUI 交互、AI 工具增强、安全管控、模型接入等维度。

外观 (Appearance)

Thinking 块显示策略、状态栏信息、工具调用展现形式。共 4 项子模块。

功能 (Feature)

自定义工具、命令、工作流自动化。共 9 项子模块，是整个扩展集中占比最大的分类。

权限 (Permission)

危险命令拦截、敏感文件访问审批。共 2 项子模块，共享同一覆盖层组件。

提示 (Prompt)

系统提示注入，在每次 AI 响应前追加自定义指令。1 项子模块。

供应商 (Provider)

自定义模型供应商接入，通过 Anthropic Messages API 兼容端点。共 6 项子模块（含 1 个公共工具模块）。

外观 (Appearance)

该分类控制终端 UI 的呈现方式：thinking 块的默认显示策略、状态栏信息、工具调用的展现形式。

默认隐藏 Thinking

将 thinking 内容默认折叠隐藏，在消息底部显示思考时长和 Ctrl+T 切换提示。通过 patch AssistantMessageComponent 的渲染逻辑，在隐藏态显示 thinking 文本尾部预览（最多 3 行），展开态完整显示。

思考时长以小时、分钟、秒格式实时更新并持久化到 session 分支中，确保跨轮次、跨会话恢复时仍能正确显示。扩展同时自动写入 settings.json 和清理默认快捷键绑定。

抑制 Thinking 状态文本

屏蔽 Ctrl+T 切换 thinking 可见性时产生的 "Thinking blocks: ..." 状态行信息，避免与其他扩展的状态栏内容产生视觉干扰。通过 monkey-patch InteractiveMode.prototype.showStatus 实现。

状态栏 Widget

在编辑器上方渲染两行终端状态栏和快捷键提示面板：

  • 第一行：模型名称、上下文使用百分比进度条、输入/输出 Token 统计、累计费用
  • 第二行：当前目录、实时 TPS、Git 分支与变更状态
  • 快捷键面板：Ctrl+O 切换工具展开、Ctrl+T 切换 thinking、Ctrl+Y 切换 yolo 模式
  • 工作计时器：当前轮次耗时和会话累计耗时，数据持久化到 session 分支

工具展示优化

OpenCode 风格的工具调用渲染扩展，提供三种预设（opencode / balanced / verbose），核心能力包括：

  • 内置工具的紧凑渲染（read/grep/find/ls/bash/edit/write）
  • 编辑/写入操作的自适应 diff 展示（split/unified 布局，语法高亮，窄窗宽度截断）
  • 流式传输中的待定编辑/写入预览（展示 pending edit / pending overwrite / pending create 差异）
  • thinking 块标签与上下文净化，防止 presentation label 回流到后续模型轮次
  • 可选的 native 用户消息框（markdown 感知渲染与 ANSI 安全处理）

功能 (Feature)

该分类是扩展集中占比最大的部分，提供自定义工具、命令、工作流自动化等能力。

AskUserQuestions 工具

通过自定义 TUI 对话框向用户提出 1-5 个带选项的问题。每个问题支持选择预设选项、输入自定义答案、或标记为"聊天讨论"。对话框支持键盘导航（方向键切换问题和选项、Enter 确认、Ctrl+C 取消），结果以结构化 JSON 返回给模型。工具执行期间自动暂停状态栏计时器。

选项 ID 设计原则

选项 ID 需要稳定且具描述性，因为选中后会原样返回给模型而非返回标签文本。

Clear 命令

注册 /clear 命令，功能等同于 /new，清空当前上下文并开启新会话。

FormFilling 工具

结构化表单填写工具，支持 2-25 个元素，字段类型包括布尔值、单选、多选、文本输入、说明文本。表单支持键盘导航、输入框支持多行文本（Shift+Enter 换行）、必填校验，提交时返回结构化 FormValue 数组。

字段类型覆盖 boolean（是/否单选）、select（单选下拉）、multiselect（多选勾选）、input（自由文本输入）和 text（只读说明文本）。

自动重试策略

在每次 session 启动时自动写入 settings.json：请求重试设为最多 10 次、基础间隔 1 秒，provider 级别最大重试等待 5 分钟。通过确保 /reload 后策略生效来保持与 Pi 内存设置的同步。

Skill 美元符引用

扩展编辑器的自动补全系统，支持 $skill:name 语法引用技能。自定义 AutocompleteProvider 拦截 $ 前缀输入，从已注册的技能命令中模糊匹配并补齐。同时注册 DollarSkillEditor 拦截退格键：删除 $skill:xxx 引用时一次退格删除整个引用标记而非逐字符删除。

在 agent_start 前扫描 prompt 中的 $skill:xxx 引用，将其映射为技能文件路径并注入到模型上下文，实现技能文件内容的按需加载。

会话统计

注册 /stats 和 /stat 命令，加载当前设备上所有历史 session 数据，以交互式全屏覆盖层展示：

  • 概览页：Token 用量（输入/输出/缓存读写）、消息数、按费用排序的模型统计、高频工具调用排行
  • 热力图页：7 天范围显示日期与小时热力图，30 天/全部范围显示星期与月热力图
  • 每日趋势图：按日期展示 token 消耗的条形趋势

支持 r 键切换时间范围（ALL TIME / 7D / 30D），方向键翻页。

pi-rewind

基于 Git 的 checkpoint/rewind 扩展，每次执行 write/edit/bash 工具后自动创建快照。核心能力：

  • /rewind 命令：checkpoint 浏览器、diff 预览、恢复三步流程
  • Esc+Esc 快捷键：快速仅文件回退
  • 智能去重：只读操作（ls/find/cat）不创建 checkpoint
  • 恢复选项：文件与对话同时恢复、仅文件、仅对话
  • 安全边界：跨分支恢复拦截、敏感目录排除、50 个上限自动修剪
  • 底部状态栏：显示当前 session 的 checkpoint 数量

性能数据

在 182K 文件、87GB 的大型 monorepo 上，每次 createCheckpoint 耗时约 142ms，负载几乎不可感知。旧 session 在启动时自动清理。

pi-rtk-optimizer

RTK 命令改写与工具输出压缩扩展，两阶段流水线：

  • 命令改写：将 bash 命令自动转为 rtk 等效命令，委托给安装的 rtk rewrite 二进制作为改写规则唯一来源，避免扩展侧维护重复规则
  • 输出压缩：ANSI 剥离、测试输出聚合、构建输出过滤、Git 输出压缩、Linter 聚合、搜索结果分组、源码注释过滤、智能截断。支持通过 /rtk 交互式设置面板按工具类型开关各压缩阶段

提供子命令：/rtk show（当前配置）、/rtk verify（rtk 可用性检查）、/rtk stats（压缩指标）、/rtk reset（恢复默认）。

pi-subagents

Claude Code 风格的自主子代理系统，提供 Agent / get_subagent_result / steer_subagent 三个工具。核心能力：

  • 默认代理类型：general-purpose（继承父 system prompt 的"父级孪生"）、Explore（只读代码探索，使用 haiku）、Plan（架构规划，只读）
  • 自定义代理：通过 .pi/agents/name.md 定义，YAML frontmatter 配置：工具集、模型、思考级别、隔离模式、轮次上限、记忆范围
  • 并行后台代理：并发队列默认 4，超出自动排队，前台代理绕过队列
  • 持久化 Widget：展示活动代理的 spinner、工具使用次数、token 消耗、上下文利用率百分比
  • 对话查看器：选择任意代理查看其完整对话的实时滚动输出
  • 优雅轮次限制：达到 max_turns 时发送 steering 消息要求收尾，额外 5 轮宽限期后才硬中断
  • Git worktree 隔离：代理在隔离副本中运行，变更自动提交到分支
  • 跨扩展 RPC：其他扩展可通过 pi.events 事件总线 spawn/stop 子代理
  • 定时调度：支持 cron / interval / one-shot 三种调度模式，session 级别持久化

权限 (Permission)

该分类提供安全管控能力：危险命令拦截、敏感文件访问审批。两个扩展共享同一个 confirmOverlay 覆盖层组件，该组件通过 patch InteractiveMode.prototype.showExtensionCustom 实现了 aboveStatus 放置模式，在状态行上方渲染自定义确认界面。

权限守卫

在 bash 工具执行前扫描命令，匹配 27 条危险规则，按严重程度（critical / high / medium）分级。规则覆盖：递归强制删除、sudo 提权、dd 磁盘覆写、mkfs 格式化、fdisk 分区修改、curl-pipe-shell、git 强制操作、Kubernetes 资源删除、敏感文件访问、系统关机重启等场景。

检测到危险命令时弹出确认覆盖层，展示匹配的规则 ID、原因和完整命令，用户可选择允许或拒绝。支持 yolo 模式（Ctrl+Y）绕过所有检查。

注意

命令规范化时会对引用字符串做去内容处理（替换为 '' 或 ""），避免引号内的敏感路径片段触发误报。同时移除安全的 stderr 重定向（2>/dev/null）以降低误报率。

敏感文件审批

在 read/write/edit 工具执行前扫描文件路径，匹配 8 条敏感文件名规则：.env 环境变量文件、包含 secret/credential/token/key 的文件名、SSH 私钥（id_rsa/id_ecdsa 等）、云服务和包管理器认证文件（.npmrc/.pypirc/.netrc）、Shell 启动配置（.bashrc/.zshrc）。

路径规范化处理将反斜杠转正斜杠并合并连续分隔符，确保跨平台一致匹配。同样支持 yolo 模式跳过检查。

提示 (Prompt)

系统提示注入

在每次 before_agent_start 事件中向系统提示注入额外的指令块。当前注入的内容是一套生产级输出纪律规范，包括：

  • Banned Output Patterns 禁止列表（代码省略符、结构性捷径、描述代替实现）
  • 输出净化纪律：禁止 Prompt Echoing、Process Leakage、Meta-commentary
  • 动态技能激活评估流程（步骤 0 检索 → 步骤 1 评估 → 步骤 2 激活 → 步骤 3 实现）
  • 执行原则、开发规范、Git Commit Message 格式、语言风格约束

注入方式

扩展通过 return { systemPrompt: event.systemPrompt + "\n\n" + extraInstructions } 在原始系统提示后追加，而非替换。扩展自身的代码中包含了完整的指令文本，修改指令只需编辑 system-prompt.ts。

架构关系

所有扩展通过各分类的 index.ts 统一导出，使用 export default async function(pi: ExtensionAPI) 签名注册到 Pi 框架。以下为扩展间的协作关系：

要点

扩展间通过 Symbol.for() 定义共享状态键、pi.events 事件总线和 pi.registerShortcut() 快捷键体系实现松耦合协作，无需模块间的直接 import 依赖。

协作关系参与扩展机制
计时器暂停/恢复 status-line、permission-gate、sensitive-file-gate、ask-user-questions、form-filling pi.events 事件 status-line:timer-pause / status-line:timer-resume
Yolo 模式共享 status-line、permission-gate、sensitive-file-gate Symbol.for("pi.extensions.yolo.active") 全局标记
Thinking 切换同步 hide-thinking-default、status-line ShortcutStateListener 机制监听 Ctrl+T 事件
技能引用与预加载 skill-dollar-reference、pi-subagents 从相同技能目录树发现 SKILL.md
覆盖层组件 confirmOverlay、form-ui-helpers 各自独立实现 aboveStatus placement，通过不同 Symbol 隔离

扩展布局约定

每个分类的 index.ts 负责导入并串联所有子模块，子模块通过独立的 export default function(pi) 导出。通用工具模块（如 form-ui-helpers.ts、env.ts、confirm-overlay.ts）被同一分类下的多个子模块共享。npm 包类型的大扩展（pi-tool-display、pi-rewind、pi-rtk-optimizer、pi-subagents）在各自目录内维护独立的 package.json 和测试体系。
